# V19: retain an existing defense plan

**Preregistered hypothesis; implementation and qualification pending.** V18
acquires durable territory but fails the stronger-control gate. Its complete
histories expose insufficient late delivery and a separate loss of useful
defender position after current visible need disappears. V19 tests bounded
continuation of an already-started defense. V2 remains the default; the
competitive objective remains unmet.

## Evidence and limits

At Juraj 439 the existing defender actually completes its target; reversing at
440 removes 17 points of stationary public route resistance. By 442 no one-step
action from its actual position closes the visible deficit. Thus simply finishing
the route is insufficient: continued physical use of the arrived defender matters.
In Amin, a large attack's terrain distance changes from ten to eleven steps at
535, disabling the inherited ten-step planner for one observation. However,
bounded path audits do not demonstrate a sufficient late rescue. Increasing a
horizon alone does not solve missing deployable force.

The winning Juraj control also makes useful releases for construction, expiration,
redeployment and outward capture. V3's remembered-force reserves and V14's
conditional service ledger already failed preservation. V19 carries no enemy
army/location estimate, adds no reserve latch and does not infer attacker identity
through fog. It retains only an actual defender under its original expiry.

## Contract

Enabled `SentinelV19Agent(retain_defense=True)` uses V18's unchanged outer
campaign with a wrapper at its actual V6 defender layer. Each step calls the
original V6 once. The default V10/V9/V8 campaign, rear expansion and nineteen-leaf
native memory remain the surrounding architecture. Disabled operation returns
the complete original V18 tuple, including telemetry and memory.

Retention requires a consecutive, unexpired and arrival-consistent original
defender, an owned fixed target, no new original defender commitment and an
original returned defender slot that has cleared. Recompute the original V6
current-visible need without treating this defender as a new donation. Retain
only when that need is absent. This includes covered visible forces and forces
outside the inherited horizon; it is not proof the enemy disappeared.

Preserve original BUILD actions, all MOVE attempts into nonowned destinations,
adjacent-threat priority and intercept guards. Invalid ownership, insufficient
observed arrival army, observation gaps and expiry release retention. A renewed
current visible need returns authority to the original V6 decision, including
new interception or release. Never extend or refresh the original expiry.

In transit, require a shortest owned route to the fixed target no longer than
the remembered remaining distance. Preserve an original full move from the
defender that already advances on such a route. Otherwise choose the first
cardinal direction, UP/DOWN/LEFT/RIGHT, that decreases that distance. This does
not introduce a new route-value optimizer. Record the actual next defender,
remaining distance and expected arrival army. Clear memory immediately when
the move reaches home: home is not a reusable field defender.

At an ordinary field target, retain the physical defender. If the original
action does not consume it, preserve that action. If an owned transfer would
consume it, choose the highest frozen campaign move score with that source
excluded, or PASS if none is positive. Original tactical capture/build priorities
remain above this substitution. Current own force and all other campaign actions
are still available; holding one unit is not a certificate that every approach
is safe or that its action opportunity cost is justified.

Keep original inner V6 proposals and commitment flags under `retained_parent_`
telemetry. Standard commitment flags must describe the actual continued or held
decision so outer campaign arbitration respects it. New events require their
actual inner issuance and the unchanged outer V9/V10/V18 action selectors.
Do not count an overwritten inner proposal as an executed action. No synthetic
parent output or second parent inference may be manufactured by a postprocessor.
The inherited `commitment_arrival_army` retains the original V6 target estimate;
`retained_expected_army` separately records the retained defender's expected
next-observation army (or current army when held), with -1 when ineligible.

## Qualification

Tests use original public V18 Amin and Juraj release histories and winning
V10-v6 release/build/capture witnesses. Distinguish an archived complete parent
tuple from public state supplied only to an isolated inner-layer test. Require
exact disabled behavior, no expiry extension across repeated retention, actual
route continuation and field holding, immediate home-arrival cleanup, priority
preservation, inconsistent/gap/expired release and truthful outer attribution.
Validate movement/retention with real game transitions where they establish a
meaningful property. Retain every failed attempt and report actual test counts.

The fixed full-call runtime contexts are V18 Amin 245/348/427, Juraj 438/439/442,
my_bot9 66, and a retained Juraj 440 continuation. That continuation may use the
original next observation only if V19's actual move at 439 matches the original
joint trajectory; otherwise qualification must explicitly document a compatible
synthetic transition rather than relabel incompatible history. Compare V19,
disabled V19 and actual V18 under identical incoming memory for each context.

Use pinned Python 3.12.10/JAX 0.11.0 on Zephyrus CPU 5, compilation cache disabled,
ten warmups and five rotated repeats of 100 synchronized full calls. Require
at least 50% of V18's median throughput in every enabled and disabled context.
Record import/first-call cost and shape reuse separately. This does not qualify
all shapes or official startup/deadlines. An independent public checker must
verify the new predicates, memory transitions, action masks and deliberately
corrupted examples before games.

## Complete development gate

Freeze source, tests, fixtures, runtime, checker and runner helpers before games.
Compare V10, V10-v6, V18 and V19 in 24 complete adaptive games: Amin 1/2, Juraj
V3.5 12/15 and original my_bot9 4/7, on the same consumed seed-83000 positions and
original keys. Use construction, deathtouch 800 and cap 1,200. V18 is the actual
parent control; V10 and V10-v6 preserve the selected stronger wins. Reserved
143000 remains untouched.

Complete exact native/public/key/telemetry/joint-action control oracles before
candidate games. Preserve original opponents, invalid actions, failures,
deadlines, exits and every attempted run. Do not tune mid-budget or restart a
healthy job. Interpret only after all 24 games and complete integrity checks.
Audit each retained route, physical holding, release, displaced action, delivered
force and entire failure; compare productive releases in the stronger controls.

V19 must win all six selected cases to advance. A locally preserved screen,
longer survival or additional income cannot replace this gate. Even six wins
would still require broader distinct-opponent coverage, fresh paired winning
evidence and valid deployment runtime before promotion.
