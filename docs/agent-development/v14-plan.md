# V14: service between collections and campaign moves

The competitive goal remains a winning advantage against every distinct tested
opponent with fresh paired evidence and valid runtime. It is not achieved. This
experiment addresses early action allocation over frozen V10; it does not add
the rejected V11–V13 capture or route vetoes.

## Activation preflight and hypothesis

The proposed V6 plus remembered-general pursuit composition cannot preserve the
selected Amin wins: the original V6/V10-v6 controls lose at 370 without revealing
an enemy general in any observation. Pursuit has no remembered target, and home
mobilization starts only at 800. The composition would retain that losing prefix.
It remains unimplemented; eighteen identity games would not repair this gap.

A different mechanism has an observable opportunity to act. In the selected
Juraj opening, V10's small collections at 100 and 106 delay a larger campaign
packet's route. In turns 100–149, V10 attempts 31 owned transfers, four neutral
captures and fifteen enemy captures; Juraj attempts 23, sixteen and eleven.
Juraj's source separates expansion service from logistics and can retain a
front-bound packet after a capture. Its service scheduler is not a universal
fairness bound: higher-tier immediate enemy captures can bypass it.

V14 tests one scheduling change, without copying Juraj's implementation or
adding its other mechanisms. An issued collecting move incurs one turn of debt.
An issued uncommitted V6 campaign move repays one turn, saturated at zero. A
new collection with outstanding debt yields to a **different eligible campaign
MOVE**. Existing plans and ready direct deployments continue; PASS or BUILD
cannot be forced as repayment. If collection and campaign propose the same
move, retain the collection and charge it once without repaying or changing
memory. This is an unvalidated one-for-one service allocation, not a theorem
that the two action classes have equal strategic value.

The actual inner V6 call supplies its proposal and campaign classification.
The class excludes explicit intercept/guard and committed-defense modes,
adjacent threat and an insufficient general reserve. It can still contain
emergency incentives from the original campaign score. It does not guarantee
neutral expansion: campaign service can itself be an owned transfer, and ready
direct deployments may continue using turns. Charge and repayment never occur
on the same decision. Repayment telemetry distinguishes servicing a move from
actually reducing an already-zero debt.

## Exact state and attribution

Enabled `SentinelV14Agent` uses `ServiceMemory(base, collection_debt)`: the
unchanged nineteen-field strategic memory plus one scalar int32 debt. Reset
that debt using incoming shape, nonmonotonic time or observation-gap evidence
before the parent updates its timestamp. Current public observations and this
per-game memory are the only policy inputs.

A deferred collection clears only its unissued offensive transport. Preserve
the actual returned V6 defender state and public enemy-general knowledge. A
parent/reference action coincidence never cancels memory. Record both complete
five-field proposals, debt/reset/charge/service/repayment, and
`service_parent_action_issued`; inherited events require this outer mask and
their existing downstream masks. Disabled `balance_collection=False` delegates
exact action, original nineteen-field memory and telemetry to frozen V10.
The disabled mode has a different static memory schema from the enabled mode.

The old-trajectory ledger starts Juraj 100 with zero debt and reaches debt three
at its second start 106. Amin 129 and 142 start at zero, but the useful collection
at 193 again has debt three. On the original Amin history, 24 of 47 collection
starts would be eligible deferrals. These are hazards, not predicted future
admissions after the candidate first changes an action. Contract fixtures insert
the new debt scalar alongside original recorded parent memory; they are not
archived V14 trajectories. The later same-action fixture 284 is explicitly a
synthetic ledger state from an already-diverged hypothetical prefix.

## Runtime, verification and decision

Use the original synchronous official-version Amin adapter with its bound
18-history/1,528-frame parity evidence. External games use the qualified original
engine and a separate synchronous official-version candidate actor. Preserve
untouched stdio opponents and their separate response limits. Use CPUs 2/14 for
Amin, CPU3 engine/CPU0 actor/CPU1 opponent externally, and CPU5 for the pre-game
matched profile, with persistent compilation cache disabled.

The matched V10/V14 profile uses original public Juraj 106 and Amin 193/129 inputs
with explicitly diagnostic debt values. Synchronize complete outputs and require
at least 50% of the parent's warm throughput on each fixture. Separate first
compilation from reused-shape calls. This gate does not qualify other shapes,
uncached startup or submission deadlines. Verify disabled parity, charged starts,
continuation, same-action agreement, actual deferral/memory clearing, resets,
independent batched debt and exact typed memory.

The selected screen merits broader evaluation only if V14 **wins both mirrored
games against each opponent** with valid actions and runtime. This preserves
the best retained control on each position: V10 wins Amin; V10-v6 wins Juraj;
both win my_bot9. A draw against Juraj or merely longer survival is insufficient.
The three placements are consumed development data, not independent fresh
strength samples. Even a passed screen requires broader control preservation,
the complete opponent census and fresh held-out competition evidence.

Deliver owned validated work and complete results to the fork's fresh
`origin/main`, preserving unrelated changes, and leave the workspace on `main`.
A rejected or inconclusive experiment keeps the full competitive goal active.
